# 02장 핵심 질문 — 컨테이너 소개

면접 대비용 핵심 질문입니다(중요도 ★★★☆☆ 이상만 수록). 답이 막히면 절 제목의 노트 링크로 돌아가세요.

> **중요도** ★★★★★ 반드시 답할 수 있어야 함 · ★★★★☆ 자주 나옴 · ★★★☆☆ 알아두면 좋음

## 이 장에서 익힐 개념

| 개념 | 한 줄 |
| :--- | :--- |
| **의존성 지옥** | 한 서버의 앱들이 서로 다른 버전을 요구해 어느 쪽도 만족시킬 수 없는 상황. **컨테이너가 나온 이유** |
| **커널 공유** | VM과 컨테이너를 가르는 단 하나의 차이. 속도·용량·격리 강도가 전부 여기서 파생됩니다 |
| **이미지 → 레지스트리 → 컨테이너** | 만들고, 보관하고, 실행하는 기본 흐름 |
| **레이어** | 이미지는 여러 겹이라 재사용됩니다. 맨 위 쓰기 레이어는 **휘발성** |
| **OCI / CRI** | 이미지 형식 표준과 런타임 인터페이스 표준. **서로 다른 규격**이라는 점이 핵심 |
| **네임스페이스** | 무엇을 **볼 수 있는지** 제한. 파드는 이걸 일부러 공유한 결과물 |
| **cgroups** | 얼마나 **쓸 수 있는지** 제한. `resources`의 실체 |

## 2.1 컨테이너 소개 — [노트](<../2.1 컨테이너 소개.md>)

> 왜 컨테이너가 나왔고 VM과 무엇이 다른가. **커널 공유** 한 단어에서 나머지 차이가 전부 파생됩니다.

1. "제 컴퓨터에서는 잘 되는데요" 문제의 실제 원인은 무엇이며, 컨테이너는 이를 어떻게 해결합니까? ★★★☆☆
2. 의존성 지옥(Dependency Hell)이란 무엇입니까? ★★★☆☆
3. 물리 서버 시대 → 가상화 시대 → 컨테이너 시대로 이어지는 흐름에서 각 단계가 해결한 문제와 남긴 한계는? ★★★★☆
4. 가상 머신과 컨테이너의 가장 근본적인 차이 한 가지는 무엇입니까? ★★★★★
5. 컨테이너가 VM보다 가볍고 빠른 이유를 커널 관점에서 설명해 보세요. 대신 무엇을 포기합니까? ★★★★★
6. 리눅스 컨테이너는 왜 윈도우나 macOS에서 그대로 돌 수 없습니까? 그런데도 Docker Desktop이 동작하는 이유는? ★★★★☆
7. 이미지 · 컨테이너 · 레지스트리 세 개념의 관계를 설명해 보세요. ★★★★★
8. 이미지가 레이어(Layer) 구조인 덕분에 얻는 이점 두 가지는 무엇입니까? ★★★★☆
9. 실행 중인 컨테이너에서 파일을 수정하면 원본 이미지는 어떻게 됩니까? 그 변경은 컨테이너를 지우면 어떻게 됩니까? ★★★★☆
10. OCI(Open Container Initiative) 표준은 무엇을 규정하며, 이 표준이 있어서 가능해진 것은? ★★★★☆
11. Docker · containerd · CRI-O · Podman · runc의 역할을 각각 한 줄로 구분해 보세요. ★★★★☆
12. 쿠버네티스 노드에서 `docker ps`가 동작하지 않는 이유와, 대신 쓰는 명령은 무엇입니까? ★★★☆☆
13. 이미지 빌드 도구로서의 Docker와 런타임으로서의 Docker를 구분해서 설명해 보세요. ★★★★★

## 2.2 컨테이너 직접 다뤄 보기 — [노트](<../2.2 컨테이너 직접 다뤄 보기.md>)

> 이미지를 만들어 띄우는 실제 흐름. 명령 암기보다 **각 옵션이 왜 필요한지**가 중요합니다.

14. 컨테이너 작업의 기본 3단계는 무엇입니까? ★★★☆☆
15. 이미지 태그로 `latest`를 쓰면 안 되는 이유는 무엇입니까? ★★★★★
16. Dockerfile의 `FROM` · `COPY` · `ENTRYPOINT`는 각각 무슨 일을 합니까? ★★★★☆
17. `ENTRYPOINT`와 `CMD`의 차이는 무엇이며, 파드 YAML의 어떤 필드가 이 둘을 덮어씁니까? ★★★★★
18. `podman run -p 8080:8080`의 의미는 무엇이며, 이 옵션 없이는 왜 접근할 수 없습니까? ★★★★☆
19. `podman run`으로 띄웠을 때와 파드로 띄웠을 때 `os.hostname()` 값이 다른 이유는 무엇입니까? ★★★☆☆

## 2.3 컨테이너를 가능하게 하는 기술 — [노트](<../2.3 컨테이너를 가능하게 하는 기술.md>)

> 컨테이너를 커널 기능으로 분해합니다. **파드가 왜 그렇게 동작하는지에 대한 근거**가 전부 여기 있습니다.

20. 컨테이너를 이루는 리눅스 커널 기능 두 가지는 무엇이며, 각각 무엇을 제한합니까? ★★★★★
21. 리눅스 네임스페이스의 종류(PID · Network · Mount · UTS · IPC · User)는 각각 무엇을 격리합니까? ★★★★☆
22. 리눅스 네임스페이스와 쿠버네티스 네임스페이스는 어떻게 다릅니까? 쿠버네티스 네임스페이스를 나누면 커널 수준 격리가 강해집니까? ★★★★★
23. 파드를 "네임스페이스를 일부러 공유하는 컨테이너 묶음"이라고 설명하는 이유는 무엇입니까? ★★★★★
24. 같은 파드의 컨테이너끼리 `localhost`로 통신할 수 있는 이유는? IP는 컨테이너마다 붙습니까, 파드마다 붙습니까? ★★★★★
25. 같은 파드의 컨테이너들이 파일 시스템은 기본적으로 공유하지 않는데, 파일을 주고받으려면 무엇이 필요합니까? ★★★★☆
26. cgroups가 없으면 어떤 사고가 납니까? (Noisy Neighbor 문제) ★★★☆☆
27. 파드 YAML의 `resources.requests`와 `resources.limits`는 각각 누가, 언제 씁니까? ★★★★★
28. CPU 한도를 초과할 때와 메모리 한도를 초과할 때의 동작이 어떻게 다릅니까? ★★★★★
