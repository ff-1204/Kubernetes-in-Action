# 03장 핵심 질문 — 쿠버네티스 API와 오브젝트 모델

면접 대비용 핵심 질문입니다(중요도 ★★★☆☆ 이상만 수록). 답이 막히면 절 제목의 노트 링크로 돌아가세요.

> **중요도** ★★★★★ 반드시 답할 수 있어야 함 · ★★★★☆ 자주 나옴 · ★★★☆☆ 알아두면 좋음

## 이 장에서 익힐 개념

| 개념 | 한 줄 |
| :--- | :--- |
| **모든 작업 = 객체 CRUD** | 쿠버네티스를 쓰는 일은 API로 객체를 만들고 고치고 지우는 것뿐입니다 |
| **kubectl은 클라이언트** | 클러스터의 일부가 아니라 HTTP 요청을 대신 만들어 주는 껍데기 |
| **선언형 `apply`** | 실무 표준. 파일이 남아 Git에 기록되고 복구됩니다 |
| **그룹 + 버전** | `apiVersion`에 적는 조합. 그룹별로 따로 버전을 올리기 위한 구조 |
| **매니페스트 5구조** | `apiVersion` / `kind` / `metadata` / `spec` / `status` — 객체 종류가 달라도 동일 |
| **spec ↔ status** | 사람이 쓰는 **목표**와 시스템이 쓰는 **현실**. 컨트롤러가 둘을 맞춥니다 |
| **레이블** | 검색·선택용. 파드가 계속 바뀌어도 **조건으로 고르기** 때문에 연결이 유지됩니다 |

## 3.1 쿠버네티스 API 이해하기 — [노트](<../3.1 쿠버네티스 API 이해하기.md>)

> 쿠버네티스를 쓴다는 것이 곧 **API로 객체를 다루는 일**임을 이해하는 절입니다.

1. "쿠버네티스는 객체를 저장하는 데이터베이스 + 그 객체를 실현하려는 컨트롤러들"이라는 표현을 설명해 보세요. 사용자가 실제로 하는 일은 무엇입니까? ★★★★☆
2. HTTP 메서드(GET · POST · PUT/PATCH · DELETE)는 각각 어떤 kubectl 명령에 대응합니까? ★★★☆☆
3. kubectl 없이도 쿠버네티스를 쓸 수 있다는 말은 무슨 뜻입니까? 이를 직접 확인하는 방법 두 가지는? ★★★☆☆
4. 명령형(`create`)과 선언형(`apply`)의 차이는 무엇이며, 실무 표준이 선언형인 이유는? ★★★★★
5. `kubectl create`와 `kubectl apply`는 대상이 이미 존재할 때 각각 어떻게 동작합니까? ★★★★☆
6. API 그룹은 왜 나누어져 있습니까? 핵심 그룹(Core)과 이름 있는 그룹의 `apiVersion` 표기가 어떻게 다릅니까? ★★★★☆
7. `apps` · `batch` · `networking.k8s.io` · `rbac.authorization.k8s.io` 그룹에 각각 어떤 객체가 속합니까? ★★★★☆
8. `v1alpha1` · `v1beta1` · `v1`의 안정성 차이는 무엇이며, 운영 환경에서 지켜야 할 규칙은? ★★★★☆
9. `kubectl api-resources` 출력의 `NAMESPACED` 열은 무엇을 뜻합니까? `true`와 `false`의 예를 각각 들어 보세요. ★★★★☆
10. 쿠버네티스가 "도구가 아니라 플랫폼"이라 불리는 근거가 되는 이유는? ★★★★☆

## 3.2 오브젝트 매니페스트 구조 — [노트](<../3.2 오브젝트 매니페스트 구조.md>)

> 객체 종류가 달라도 **뼈대는 항상 같습니다.** 이 구조 하나면 처음 보는 YAML도 읽힙니다.

11. 모든 쿠버네티스 객체가 공유하는 다섯 개 최상위 필드는 무엇입니까? ★★★★★
12. `spec`과 `status`는 각각 누가 씁니까? 컨트롤러가 하는 일을 이 둘로 설명해 보세요. ★★★★★
13. `apiVersion`을 잘못 적으면 어떤 오류가 나며, 올바른 버전은 어떻게 확인합니까? ★★★☆☆
14. 레이블(labels)과 어노테이션(annotations)의 차이를 목적 · 검색 가능 여부 · 길이 제한으로 구분해 보세요. ★★★★★
15. 서비스가 어떤 파드로 요청을 보낼지 고르는 기준은 무엇입니까? ★★★★★
16. `uid`와 `resourceVersion`은 각각 어떤 역할을 합니까? 쿠버네티스는 객체를 이름으로 구분합니까, uid로 구분합니까? ★★★☆☆
17. 두 사람이 같은 객체를 동시에 수정하면 어떻게 됩니까? (낙관적 잠금) ★★★☆☆
18. Deployment의 `spec.template` 안쪽은 사실상 무엇입니까? Pod 매니페스트와 무엇이 다릅니까? ★★★★★
19. `selector.matchLabels`와 `template.metadata.labels`가 일치하지 않으면 어떤 일이 벌어집니까? ★★★★★
20. `status`에는 어떤 정보가 담깁니까? 특정 값만 뽑아내려면 어떤 명령을 씁니까? ★★★☆☆
