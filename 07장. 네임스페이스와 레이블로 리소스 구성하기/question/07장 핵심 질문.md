# 07장 핵심 질문 — 네임스페이스와 레이블로 리소스 구성하기

면접 대비용 핵심 질문입니다(중요도 ★★★☆☆ 이상만 수록). 답이 막히면 절 제목의 노트 링크로 돌아가세요.

> **중요도** ★★★★★ 반드시 답할 수 있어야 함 · ★★★★☆ 자주 나옴 · ★★★☆☆ 알아두면 좋음

## 이 장에서 익힐 개념

| 개념 | 한 줄 |
| :--- | :--- |
| **네임스페이스** | 오브젝트를 묶는 **이름 구역**. 리눅스 네임스페이스와 이름만 같습니다 |
| **격리가 아님** | 네트워크도 노드도 안 나뉩니다. 막으려면 **NetworkPolicy**가 따로 필요 |
| **소속 vs 전역** | 모든 오브젝트가 네임스페이스에 속하지는 않습니다. 노드·PV는 클러스터 전역 |
| **레이블** | 이름 하나로는 못 만드는 **여러 축의 분류**를 만듭니다 |
| **셀렉터** | 레이블로 고르는 조건식. **AND만 있고 OR는 없습니다** |
| **필드 셀렉터** | 사람이 붙이지 않은 **원래 값**으로 고르기. 쓸 수 있는 필드가 제한적 |
| **애노테이션** | **고를 수 없는 대신** 길이가 자유로운 기록용 |

## 7.1 네임스페이스로 오브젝트 나누기 — [노트](<../7.1 네임스페이스로 오브젝트 나누기.md>)

> 이름이 같을 뿐 **리눅스 네임스페이스와 무관하다**는 것, 그리고 **격리가 아니다**라는 것. 이 두 가지가 이 절의 전부입니다.

1. 쿠버네티스 네임스페이스와 리눅스 네임스페이스는 어떻게 다릅니까? 각각 무엇을 나눕니까? ★★★★★
2. `dev`와 `prod` 네임스페이스로 나누면 커널 수준의 격리가 강해집니까? ★★★★★
3. 리눅스 네임스페이스를 공유하는 단위는 무엇입니까? ★★★★☆
4. 네임스페이스가 실무에서 해 주는 일을 네 가지로 정리해 보세요. ★★★★☆
5. 클러스터에 처음부터 있는 네임스페이스 네 개와 각각의 역할은? ★★★★☆
6. 모든 오브젝트가 네임스페이스에 속합니까? 속하는 것과 전역인 것을 가르는 판단 기준은 무엇입니까? ★★★★★
7. 어떤 리소스가 네임스페이스 소속인지 확인하는 명령은? ★★★☆☆
8. 네임스페이스 이름 규칙은 무엇이며, `my_namespace`나 `MyNamespace`가 거부되는 이유는? ★★★★☆
9. 서로 다른 네임스페이스의 파드가 통신할 수 있습니까? 막으려면 무엇이 필요합니까? ★★★★★
10. 네임스페이스를 삭제하면 어떤 일이 벌어집니까? `Terminating`에서 멈추는 경우의 원인은? ★★★★☆

11. 이름에 규칙을 넣어 분류하는 방식의 한계는 무엇이며, 레이블은 그것을 어떻게 해결합니까? ★★★★★
12. 레이블 키의 구조를 설명하고, 각 부분의 길이 제한을 말해 보세요. ★★★★☆

14. `kubectl label`로 이미 있는 레이블을 바꾸려면 무엇이 필요하며, 그런 안전장치를 둔 이유는? ★★★★☆
15. `app.kubernetes.io/name` 같은 표준 레이블을 쓰면 무엇이 좋습니까? ★★★☆☆
16. 실행 중인 파드의 레이블을 바꾸면 컨트롤러 입장에서 무슨 일이 벌어집니까? 이것을 디버깅에 어떻게 활용합니까? ★★★★★

## 7.3 레이블 셀렉터로 오브젝트 걸러 내기 — [노트](<../7.3 레이블 셀렉터로 오브젝트 걸러 내기.md>)

20. 레이블 셀렉터의 진짜 쓰임은 kubectl이 아니라 어디입니까? 서비스와 파드 중 **고르는 쪽**은 누구입니까? ★★★★★
21. `matchLabels`와 `matchExpressions`는 언제 각각 씁니까? `Exists` 연산자에서 주의할 점은? ★★★★☆

23. `nodeSelector` 조건에 맞는 노드가 하나도 없으면 파드는 어떻게 됩니까? 에러가 납니까? ★★★★★
